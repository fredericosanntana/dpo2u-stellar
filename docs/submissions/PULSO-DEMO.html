Architecture

Four layers, one policy carried end to end

The registry decides validity; the ASP membership set admits; the DPO2U-controlled blocked lane enforces revocation; the external audited instance stays publicly readable but not writable by us.

Honest boundary

Two non-membership instances — only one is ours to write

The blocked lane is fully operable because it runs on the instance DPO2U controls. The externally audited instance is read-only to us. We surface this difference instead of blurring it.

Operated by DPO2U

asp-non-membership · CAEJBGQD…EUUS

  • Insert / delete executed with dpo2u-deployer.
  • Registry revoke → blocked-lane insert coupled and confirmed on-chain.
  • Automatable with an idempotent revocation watcher.
External · audited

asp-non-membership · CDREZXZI…K3O3

  • Public reads work: get_root, find_key, verify_non_membership.
  • We cannot insert_leaf / delete_leaf — both require the external admin's auth.
  • No alternate public surface exists to mutate it without that key.
The remaining gap is governance/authority, not integration feasibility. Unifying the two would require delegated admin on the external instance, or redeploying to an instance governed by a key under our explicit operation. Source: S8.
What this demo does and does not assert

Proven now · DPO2U-controlled · cannot be mutated externally

✓ Proven now

  • Live registry deployed; verify_attestation_proof = true for a valid attestation.
  • Admission payload extracted from the live registry decision.
  • Membership insert_leaf executed; Merkle root changed on-chain.
  • Canonical revoke flips verify/active to false; re-entry rejected fail-closed.

⚙ DPO2U-controlled infra

  • Blocked-lane insert_leaf on instance CAEJBGQD…EUUS.
  • Registry revoke coupled to non-membership block, end to end.
  • Idempotent watcher can automate the coupling.
  • This is a testnet walkthrough — not a claim of production pool readiness.

✕ Cannot mutate externally

  • External audited instance CDREZXZI…K3O3 stays read-only to us.
  • Mutation requires admin GDF4BXPQ…QORC, which we do not hold.
  • We make no claim of permissionless mutation of the audited instance.
