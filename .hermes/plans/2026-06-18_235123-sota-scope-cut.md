# SOTA Scope Cut — DPO2U Stellar/ZK Implementation Plan

> **For Hermes:** Use subagent-driven-development / claude-code only after the founder approves the cut line below. Do not try to build every SOTA item in one sprint.

**Goal:** Define the narrowest credible package that materially upgrades the current hack slice toward the whitepaper without collapsing under over-scope.

**Architecture:** Preserve the current proven B-first spine (`registry -> ASP -> blocked lane -> watcher`) and concentrate upgrades on public-verifier maturity, lifecycle semantics, and disclosure. Defer network effects, production privacy pool, and large-scale cryptographic ceremony/governance until after the public base is hardened and externally auditable.

**Tech Stack:** Soroban contracts, BN254/Groth16 verifier path, current `protocol-registry`, `asp-mvp`, `privacy-pool`, watcher scripts, docs package.

## Why this cut is correct

Current repo evidence proves:
- real registry verification + revocation
- real ASP mutation and blocked-lane on DPO2U-controlled instance
- real watcher/idempotent automation
- real BN254/Groth16 verification in the ZK vertical
- symbolic-stateful privacy-pool with honest limits
- explicit docs saying testnet/devnet, dev VK, no production MPC, no token custody, no decentralized governance

So the next honest upgrade is **public-verifier maturity**, not a fake jump to full privacy infrastructure or decentralized network claims.

## Package B — Selective Disclosure / View-Key bounded MVP (should-ship)

### Objective
Deliver a robust but bounded disclosure story that matches the whitepaper better without pretending the final privacy architecture is done.

### Scope
- define authorized disclosure actors
- specify exactly what is revealed and under what authorization
- prove consistency between sealed verdict and disclosed payload/hash
- document trust model and revocation/rotation behavior

### Out of scope
- full institution-grade multi-party key management
- regulator-integrated production ops
- universal disclosure network

### Files likely to change
- new disclosure contract/module docs
- possibly new contract package if a small disclosure helper is introduced
- docs: `A-READINESS-PLAN.md` only if governance impacts disclosure authority

### Validation
- unit tests for auth and consistency
- explicit examples of disclosed vs non-disclosed fields
- docs with threat boundaries

## Package D — Open Standard draft (must-ship)

### Objective
Convert the protocol from repo behavior into a portable spec.

### Deliverables
- terminology glossary
- required interfaces
- verification invariants
- revocation/freshness semantics
- claim/jurisdiction/profile/stake scope semantics
- conformance profile: `demo`, `public-base`, `production-target`

### Why it matters
This gives you a truthful answer to the whitepaper gap: the protocol is becoming standardizable even before the full decentralized network exists.

### Objective

### Deliverables

- MPC ceremony gates

## Explicit no-go items for this sprint

### 1. Verifier network descentralizado
Too much governance + economics + operations. Document the model; do not build/claim it now.

### 2. Pool privado production-grade
Current pool is explicitly symbolic-stateful, not value-moving. Closing this honestly is a major separate track.

### 3. MPC ceremony madura
A real ceremony is a standalone milestone with external coordination and artifact handling. Not a hack-sprint add-on.

### 4. Anonimato de escala
Current depth-4 vertical slice is not production anonymity. Do not blur that line.
