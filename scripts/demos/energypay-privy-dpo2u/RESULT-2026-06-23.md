# EnergyPay × Privy × DPO2U — Phase-1 live run (2026-06-23)

The full tri-layer composability, end to end on Stellar testnet, with **our**
credentials (DPO2U Privy app + the Phase-0 operator wallet). This is the proof to
later offer EnergyPay.

## Flow

`Privy (operator signer) → DPO2U admit() (decides + evidence bound to the action)
→ Stellar settlement (executes) → evidence hash pinned on-chain (memo)`.

## ALLOW lane ✅

- Operator (Privy wallet): `GCGPXORXCF2DLCYSYZ652DCDRAFKXAXZLJFL2YXOOWHWSOLVUDSZXZAQ`
- DPO2U `admit` → **ALLOW** ("within settlement mandate + operator admitted")
- Evidence hash (bound to the exact action): `e36d0ba59ce1e0418fb8a4ef9cc526d05b548c14d0876f9f667711eeb0f5cc32`
- Privy raw-signed the settlement; submitted:
  **tx `f657871db7bdf3db237820543f0bb8879bdc2596a204ef1875243a282a620d02`**
  ([explorer](https://stellar.expert/explorer/testnet/tx/f657871db7bdf3db237820543f0bb8879bdc2596a204ef1875243a282a620d02))
- **On-chain verification:** the tx `memo_type=hash`, `memo` decodes to
  `e36d0ba5…f5cc32` — **identical to the DPO2U evidence hash** — and the
  `source_account` is the Privy wallet. The evidence travels with the transaction.

## DENY lane ✅

- Same operator, amount over mandate (100,000 XLM).
- DPO2U `admit` → **DENY** ("amount exceeds settlement mandate")
- **The Privy signature was never requested — settlement blocked fail-closed.**
  Nothing settled (the deny is the proof — Nicole's primary criterion).

## What this proves

- **Privy** signs a real Stellar settlement (raw-sign over the tx hash) — verified
  by Horizon accepting the signature and the source being the Privy wallet.
- **DPO2U** is the decision layer: allow/deny, with an evidence hash bound to the
  exact action (Tyler's TOCTOU fix — re-derived + checked before signing).
- **Settlement** executes only on `allow`; the evidence hash is pinned on-chain.
- **Deny** prevents the signature — the gate is the thing that decides, not a dashboard.

## Honest boundaries

- Settlement here is a native-XLM testnet payment standing in for EnergyPay's
  energy settlement; the DPO2U gateway policy is a demo policy (amount mandate +
  operator allowlist). The architecture is the F1 design; the policy/asset are
  illustrative.
- Off-chain admission (F1). On-chain enforcement of the action↔evidence binding is
  Phase 2's gate (DeFindex). Mainnet/governance not in scope.
- Run with DPO2U's Privy app; for production the app is EnergyPay's.
